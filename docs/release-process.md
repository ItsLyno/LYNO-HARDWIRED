# Выпуск сборки и лаунчера

Пошаговая инструкция для автора сборки. Как устроена раздача, описано в
[README](../README.md#как-устроена-раздача).

## Права на моды

Сборка перезаливает чужие моды в публичные GitHub Releases. Многие авторы на
Nexus это запрещают: смотрите вкладку **Permissions → Upload permission** на
странице мода. Моды без разрешения не включайте в сборку или спросите автора.
Лаунчер это никак не проверяет.

## Один раз: подготовка

1. **Портативный инстанс MO2** вне папки игры: `ModOrganizer.exe`,
   `portable.txt`, `ModOrganizer.ini`, `mods\` и `profiles\` в одной папке.
   Если инстанс глобальный, поставьте MO2 заново как Portable и скопируйте
   туда `mods\`, `profiles\` и `overwrite\`.
2. **Профиль сборки** (по умолчанию `LYNO`, другое имя задаётся через
   `--profile`). В настройках профиля выключите локальные сохранения и
   профильные настройки игры.
3. **Инструменты:** Rust (<https://rustup.rs>, с Visual Studio C++ Build Tools),
   Git, GitHub CLI (`gh auth login`).
4. **Сборка утилиты:**
   ```powershell
   git clone https://github.com/ItsLyno/LYNO-HARDWIRED.git
   cd LYNO-HARDWIRED
   cargo build --release -p lyno-pack
   ```

## Перед каждым выпуском

1. Запустите игру, всё настройте и закройте игру и MO2.
2. Перенесите настройки из **Overwrite** в мод `LYNO Settings` (ПКМ по
   Overwrite → Create Mod или перетаскивание). Мод должен стоять последним среди
   модов сборки, в `meta.ini` у него должно быть `[LYNO]` `id=lyno-settings`.
   Подробнее: [README → Настройки модов](../README.md#настройки-модов).
3. Узнайте версию игры: свойства `bin\x64\Cyberpunk2077.exe` → Подробно.

## Выпуск

```powershell
git pull
.\target\release\lyno-pack.exe build "D:\Modding\MO2" --profile "LYNO" `
  --version 1.1.0 --game-version 2.31 --note "Что изменилось" --out out
```

- Прошлую версию утилита берёт из опубликованного `build/manifest.json`.
  Загружаются только новые и изменённые моды, их список печатается в конце
  (`To upload`). Если там мод, который вы не трогали, значит внутри него
  изменился файл (обычно конфиг). Разберитесь до загрузки.
- Прочитайте все строки `warning:`.
- Моды под разделителем `LYNO USER MODS` в сборку не попадают: это ваши
  личные моды и эксперименты. Чтобы мод ушёл игрокам, перетащите его в MO2
  выше этого разделителя. Такие моды перечислены в предупреждении.
- Ключ Nexus (`$env:NEXUS_API_KEY`) нужен, чтобы в лаунчере были авторы модов.

Затем опубликуйте:

```powershell
.\target\release\lyno-pack.exe publish --out out
```

Утилита делает всё по порядку и останавливается на первой ошибке:

1. Проверяет, что вы в клоне репозитория, в ветке `main`, она совпадает с
   `origin/main`, а эта версия ещё не опубликована.
2. Создаёт релиз `build-1.1.0` (заметки берутся из `--note`) и загружает
   новые части. Уже загруженные пропускает, поэтому после обрыва просто
   запустите `publish` ещё раз.
3. Проверяет по HTTP каждую часть манифеста, включая части из старых
   релизов. Если что-то не скачивается, манифест не пушится.
4. Спрашивает подтверждение (`--yes` — без вопроса), копирует
   `out\manifest.json` в `build\manifest.json`, коммитит `Build 1.1.0` и
   пушит в `main`.

Как только манифест появится в `main`, лаунчеры начнут скачивать новую
версию. raw.githubusercontent.com кэширует файл на несколько минут.

Если `push` не прошёл, коммит остаётся локальным: выполните `git push`.

Если прервалась сама упаковка, запустите ту же команду `lyno-pack build` ещё раз:
готовые пакеты подхватятся. Повторные запуски быстрые: неизменённые моды не
перечитываются (кэш хэшей в `.lyno\pack-cache.json` внутри инстанса).
Первая упаковка сборки на сотни гигабайт всё равно идёт долго: её скорость
упирается в диск. Чтобы ускорить, держите `--out` на другом диске (лучше SSD)
и добавьте папку инстанса и `out` в исключения Защитника Windows.

## Выпуск из папки лаунчера (режим автора)

Можно не держать отдельный MO2: играть и править моды прямо в папке, куда
сборку поставил лаунчер, и выпускать версии оттуда.

1. Поставьте опубликованную сборку лаунчером как обычный игрок.
2. Настройки → **Режим автора**. Обновление и починка выключатся: иначе
   лаунчер откатил бы ваши правки. Появится вкладка **Выпуск**.
3. Правьте моды в MO2 (кнопка в лаунчере открывает именно эту папку).
   Новые моды MO2 ставит в конец списка, под `LYNO USER MODS`: чтобы мод
   ушёл игрокам, перетащите его выше разделителя.
4. Вкладка **Выпуск** показывает, что изменилось с установленной версии:
   новые, удалённые, переименованные, включённые и выключенные моды, порядок,
   а по кнопке «Проверить файлы» — изменённые файлы и настройки внутри модов.
5. Соберите и опубликуйте выпуск командами выше, указав папку лаунчера как
   инстанс (Настройки → Папки → Сборка). `--out` держите вне этой папки.
6. В лаунчере на вкладке **Выпуск** нажмите **Принять <версия>**: лаунчер
   запишет опубликованную версию как установленную, ничего не скачивая, и
   изменения дальше считаются от неё.

Старый отдельный MO2 после перехода больше не нужен. Если в нём остались
неопубликованные правки, сначала выпустите их из него, потом переходите.

## Нельзя

- Удалять старые релизы `build-*`: неизменённые моды скачиваются из них.
- Переименовывать папку мода без `[LYNO] id=`: для лаунчера это новый мод.
- Пушить манифест вручную, минуя `publish`: так легко опубликовать сборку с недозагруженными файлами.

## Лаунчер

Лаунчер обновляет себя сам: при запуске он читает `launcher/latest.json` из
`main` и, если там версия новее, предлагает обновиться. Установщик подписан,
и лаунчер не поставит файл, подпись которого не сходится с ключом в
`tauri.conf.json`.

### Один раз: ключ подписи

1. Создайте ключ (пароль запомните):
   ```powershell
   cd apps\launcher
   pnpm tauri signer generate -w $env:USERPROFILE\.tauri\lyno-hardwired.key
   ```
2. Содержимое `lyno-hardwired.key.pub` вставьте в `apps/launcher/src-tauri/tauri.conf.json`
   → `plugins.updater.pubkey` и закоммитьте. Пока ключ пустой, лаунчер
   обновления не ищет.
3. В репозитории: Settings → Secrets and variables → Actions → New repository secret:
   `TAURI_SIGNING_PRIVATE_KEY` — содержимое `lyno-hardwired.key`,
   `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — пароль.

Приватный ключ храните в надёжном месте и никуда не коммитьте. Если его
потерять, выпустить обновление, которое примут установленные лаунчеры,
будет нельзя: игрокам придётся один раз переустановить лаунчер вручную.

### Выпуск

1. Поднимите версию в `apps/launcher/src-tauri/tauri.conf.json`,
   `apps/launcher/package.json` и `[workspace.package]` корневого `Cargo.toml`.
2. Запушьте в `main` и дождитесь зелёного CI.
3. Actions → **Launcher release** → Run workflow (ветка `main`), в поле
   «Что нового» коротко опишите изменения: игроки увидят это в лаунчере.

Workflow собирает и подписывает установщик, создаёт релиз `launcher-v<версия>`
(он становится Latest — оттуда игроки скачивают лаунчер), и только после
этого коммитит `launcher/latest.json` в `main`. Если `main` защищена от
пушей, разрешите их для GitHub Actions или закоммитьте `latest.json` из
релиза вручную.

Лаунчеры версии 0.1.0 автообновления не умеют: их игрокам нужно один раз
поставить новую версию вручную.

Если меняется схема манифеста (`SCHEMA_VERSION`), сначала выпустите лаунчер и
дайте игрокам обновиться, и только потом публикуйте сборку в новом формате:
лаунчер принимает только свою версию схемы.

## Отчёты игроков

Настройки → Диагностика → **Собрать отчёт** сохраняет на рабочий стол
`LYNO-report-<дата>.zip`: `summary.txt` (версии, пути, статус), логи
лаунчера, MO2, RED4ext, CET и redscript (из `overwrite/` и папки игры),
`modlist.txt`, `state.json`. Большие логи обрезаются до последних 2 МБ.
Попросите игрока прислать этот файл вместо описания вылета.
