# MO2 instance format

What the launcher reads and writes in a portable MO2 instance. Code:
`crates/core/src/{mo2,modlist,meta}.rs`.

## Layout (portable instance)

```
<instance>/
  ModOrganizer.exe, *.dll, plugins/, python/, stylesheets/ …   MO2 itself
  portable.txt                    marks the instance as portable (data next to the exe)
  ModOrganizer.ini                instance settings, game path, executables, plugin settings
  profiles/<profile>/             modlist.txt, settings.ini, plugins.txt, archives.txt …
  mods/<folder>/                  one folder per mod, with meta.ini
  mods/<title>_separator/         separators are empty mod folders
  overwrite/                      new files the game created through the VFS
  downloads/, logs/, crashDumps/, webcache/
  .lyno/                          launcher state (not MO2): state.json, manifest.json,
                                  cache/, staging/, overwrite-backup/<version>/
```

A *global* instance keeps the data in `%LOCALAPPDATA%\ModOrganizer\<name>` instead,
apart from the exe. The build must be made from a portable instance: the base
package is the instance root.

## `profiles/<profile>/modlist.txt`

```
# This file was automatically generated by Mod Organizer.
+Highest priority mod
-Disabled mod
+Lowest priority mod
*DLC: EP1
```

- First line = **highest** priority (wins conflicts). The MO2 UI shows the reverse.
  `ModList` keeps entries in UI order (lowest first) and flips on read/write.
- `+` enabled, `-` disabled, `*` unmanaged (game DLC, foreign files).
- Separators: `<title>_separator` (always `-`).
  The color picked in MO2 lives in the separator's `meta.ini` as `[General] color=@Variant(...)`:
  QSettings-escaped QDataStream bytes of a QColor (`\0\0\0\x43` type id, spec `\x1` = RGB, then
  16-bit alpha, red, green, blue). `lyno-pack` turns it into `#rrggbb` in the manifest; the launcher
  shows it in the mod list and writes it back into the player's separator (`meta::qt_color`, `meta::save_color`).

## `overwrite/`

Files the game and its tools create through the VFS (CET and RED4ext settings, logs) land
here, above every mod. The launcher shows it as the last row of the list, like MO2, and
can turn it into a mod (MO2's "Create Mod": the folder moves to `mods/<name>`) or empty it.

## `mods/<folder>/meta.ini`

Fields used: `[General]` `modid`, `version`, `gameName`, `installationFile`,
`repository`; `[installedFiles]` `1\modid`, `1\fileid`. MO2 rewrites this file on
its own (update checks add `lastNexusQuery`, `nexusLastModified`, …), so the build
ships it but leaves it out of the package hash (`rules::is_hashed`).

Launcher section:

```ini
[LYNO]
id=lyno-settings
```

`id` is the stable package id across builds. Without it the id is a slug of the
folder name, and renaming the folder makes it a new mod (full re-download).

## `profiles/<profile>/settings.ini`

- `[General]` `LocalSaves=true|false` — profile-specific saves in `profiles/<p>/saves/`.
- `[General]` `LocalSettings=true|false` — profile-specific game ini files; for
  Cyberpunk that is `UserSettings.json`, copied into the profile folder.
- `[General]` `AutomaticArchiveInvalidation` — Bethesda only.
- `[forced_libraries]` — per-executable forced load libraries (`<exe>/enabled`, list).
  The Cyberpunk plugin provides `version.dll` and `winmm.dll` for `Cyberpunk2077.exe`.

`lyno-pack` warns when `LocalSaves` or `LocalSettings` is on: those files are never
shipped.

## `ModOrganizer.ini`

- `[General]` `gamePath=@ByteArray(D:/…/Cyberpunk 2077)`, `selected_profile`.
- `[customExecutables]` `N\title`, `N\binary`, `N\arguments`, `N\workingDirectory`
  (absolute paths into the game folder), `N\hide` (left out of MO2's menu). The launcher
  offers every entry but the game's on Home and starts it with `run -e "<title>"` (`Instance::executables`).
- `[Plugins]` per-plugin settings, e.g. `Cyberpunk 2077 Support Plugin\enforce_archive_load_order=true`.
- Qt ini: backslashes may be escaped (`D:\\Games\\…`).

After install and every update the launcher rewrites every occurrence of the
author's game path to the player's (`Instance::set_game_path`). Other absolute
paths (tools outside the game folder, custom `download_directory`/`mod_directory`)
are not rewritten — keep them default in the build.

MO2 rewrites `[Geometry]`, `[Widgets]`, `[recentDirectories]` and `[Servers]` (window
layout, expanded separators, file dialog folders, Nexus CDN with the day last seen) on
every run. The build ships the file without them (`mo2::strip_ui_state`, packed from a
copy in `.lyno/pack/`), otherwise every build would repack and re-upload the base.

The base package overwrites `ModOrganizer.ini` on each base update, so the player's
own MO2 settings reset (known limitation).

## Command line

- `ModOrganizer.exe -p <profile> run -e "<executable title>"` — start an executable
  inside the VFS; forwarded to a running MO2.
- `ModOrganizer.exe -p <profile>` — open MO2 on a profile.
