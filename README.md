# LYNO//HARDWIRED

Лаунчер сборки модов Cyberpunk 2077 на базе Mod Organizer 2.

Сборка целиком раздаётся через GitHub Releases этого репозитория: портативный MO2 с настроенным инстансом и все моды. Лаунчер устанавливает и обновляет сборку, прописывает путь к игре, запускает её через MO2 и показывает список модов с авторами и ссылками на Nexus Mods.

## Как устроена раздача

- `build/manifest.json` в ветке `main` описывает актуальную версию: changelog, порядок модов, автор и ссылка на Nexus у каждого мода, пакеты.
- Каждый мод — отдельный пакет `tar.zst`, разрезанный на части не больше 1,9 ГБ (лимит GitHub на файл в релизе — 2 ГБ).
- Пакеты адресуются по хэшу содержимого. Если мод не изменился, манифест продолжает ссылаться на файл из старого релиза: в новый релиз заливаются только изменённые моды, и пользователи скачивают только их.
- Базовый пакет содержит MO2 и конфиг инстанса (`ModOrganizer.ini`, профиль сборки) без `mods/`, `downloads/`, `overwrite/` и логов. После установки лаунчер переписывает в `ModOrganizer.ini` пути к игре на пути пользователя.
- Моды, которые пользователь сам добавил в MO2, при обновлениях не трогаются: они остаются под разделителем `LYNO USER MODS`.
- Если в сборке есть REDmod-моды (`mods/<имя>/info.json`), лаунчер запускает игру через `Cyberpunk 2077 (REDmod)`: MO2 перед запуском разворачивает их с порядком из MO2. Без установленного DLC REDmod лаунчер не запустит игру и скажет, что его нужно поставить.

## Что попадает в сборку

Правила описаны в `crates/core/src/rules.rs`. Они основаны на [плагине Cyberpunk для MO2](https://github.com/ModOrganizer2/modorganizer-basic_games/wiki/Game:-Cyberpunk-2077) и на том, куда пишут свои файлы CET, RED4ext, redscript и Mod Settings.

| Что | Где | В сборке |
|---|---|---|
| Порядок модов, разделители, вкл/выкл | `profiles/<профиль>/modlist.txt` | через манифест |
| MO2, его плагины и их настройки | корень инстанса, `plugins/`, `ModOrganizer.ini` | в базовом пакете |
| Настройки профиля | `profiles/<профиль>/settings.ini` и т.п. | в базовом пакете |
| Настройки модов, которые лежат внутри мода | `mods/<мод>/...` | вместе с модом |
| Настройки модов, которые игра создала сама | `overwrite/` | **нет**, пока вы не перенесёте их в мод (см. ниже) |
| Кэш redscript и REDmod, копии кэшей игры | `r6/cache/` | никогда: собирается под версию игры на каждой машине |
| Порядок архивов от плагина MO2 | `archive/pc/mod/modlist.txt` | никогда: плагин пересоздаёт его перед запуском |
| Логи | `*.log`, `r6/logs/`, `red4ext/logs/` | никогда |
| Локальные сохранения и `UserSettings.json` профиля | `profiles/<профиль>/saves/`, `UserSettings.json` | никогда: это ваши сохранения и графика под ваше железо |

`meta.ini` мода упаковывается, но не входит в хэш пакета. MO2 сам переписывает его при проверке обновлений, и без этого после каждой проверки мод перезаливался бы целиком.

### Настройки модов

Когда мод впервые сохраняет настройки, MO2 кладёт новый файл в `overwrite/`. Примеры: `red4ext/plugins/mod_settings/user.ini` (Mod Settings), json-файлы и `db.sqlite3` модов CET в `bin/x64/plugins/cyber_engine_tweaks/mods/<мод>/`. Чтобы файл попал в сборку:

1. Настройте моды в игре и закройте её.
2. В MO2: ПКМ по **Overwrite** → **Create Mod…**, например `LYNO Settings`. Если такой мод уже есть, перетащите файлы из Overwrite в него.
3. Поставьте этот мод последним среди модов сборки, чтобы его файлы перекрывали остальные.
4. Пропишите ему постоянный id в `meta.ini`: секция `[LYNO]`, ключ `id=lyno-settings`.

Логи и кэши переносить не нужно, а если перенесёте, `lyno-pack` их всё равно не упакует. Если в `overwrite/` остались файлы, которые не попадут в сборку, `lyno-pack` напишет об этом.

У игрока файл из `overwrite/` перекрывает любой мод. Поэтому при установке или обновлении мода сборки лаунчер переносит из `overwrite/` игрока файлы с теми же путями в `.lyno/overwrite-backup/<версия>/`, и настройки сборки применяются. Файлы внутри модов сборки при обновлении мода заменяются целиком: правки игрока в них пропадают, это нужно учитывать.

Не держите настройки внутри тяжёлых модов. Если мод переписал свой конфиг внутри своей папки, у него меняется хэш, и игроки скачают весь мод заново. В выводе `lyno-pack` это видно по строке `<мод>: packing N MB` у мода, который вы не обновляли. Такой файл перенесите в `LYNO Settings`, а сам мод переустановите начисто.

### Опциональные моды

Мод, который игрок может выключить (тяжёлые текстуры, пресет графики, спорная механика), пометьте в его `meta.ini`:

```ini
[LYNO]
id=hd-reworked
optional=true
```

- В лаунчере у такого мода появляется переключатель на странице «Моды». Выключенный мод остаётся установленным и обновляется вместе со сборкой, MO2 его просто не подключает.
- Выбор игрока хранится в его `modlist.txt` и переживает обновления сборки, в том числе если игрок переключил мод прямо в MO2. Состояние мода в вашем профиле (вкл/выкл) — значение по умолчанию для новых игроков.
- Остальные моды сборки при каждом обновлении включаются и выключаются так, как в вашем профиле: если игрок выключит в MO2 обязательный мод, следующее обновление включит его обратно.
- Не делайте опциональным мод, от которого зависят другие моды сборки: лаунчер зависимостей не проверяет.

## Проверка целостности

«Настройки» → «Диагностика» → «Проверить файлы». Лаунчер перечитывает каждый файл каждого мода сборки и сравнивает его с хэшем, записанным при установке (`.lyno/files/`). У базового пакета он проверяет, что все файлы на месте. `meta.ini`, логи и кэши (`rules::is_generated`) не проверяются: их пишут MO2 и игра.

- Отчёт по каждому моду: каких файлов нет, какие изменены, какие лишние.
- Изменённый файл настроек (`.json`, `.ini`, `.toml`, `.cfg`, `.xml`, `.sqlite3`… — `rules::is_settings`) повреждением не считается. Игра через MO2 переписывает такие файлы прямо в папке мода, когда игрок меняет настройки. Лаунчер показывает их отдельно как «изменены настройки». Это угадывание по расширению: испорченный конфиг тоже попадёт в настройки, для этого есть «Сбросить и настройки».
- Повреждённый мод чинится целиком: пакет — один поток `tar.zst`, отдельный файл из него не скачать. Изменённые игроком файлы настроек при починке переносятся в новую копию мода, если не отмечено «Сбросить и настройки».
- Хэши файлов хранит лаунчер, в манифест они не входят: иначе манифест сборки из сотен модов весил бы мегабайты. Для модов, установленных до появления проверки, хэши записываются при первой проверке, если мод цел. Если не цел, лаунчер покажет только «файлы изменены» без подробностей.
- Файлы базового пакета, которые MO2 переписывает сам (`ModOrganizer.ini`, настройки профиля), проверяются только на наличие.
- Починка — это обычное обновление: выбранные моды помечаются в `state.json` и скачиваются заново так же, как при обновлении, с докачкой и продолжением после сбоя. Если вышла новая версия сборки, она установится заодно. Отметок «обновлён» починка не ставит.

## Как выпустить версию сборки

Нужны `cargo` и [GitHub CLI](https://cli.github.com/) с доступом к репозиторию.

```sh
cargo build --release -p lyno-pack

target/release/lyno-pack build "D:\Modding\LYNO" ^
  --profile LYNO --version 1.4.0 --game-version 2.31 ^
  --note "Обновлены CET и RED4ext под 2.31" --note "Добавлен Better Vehicle Handling" ^
  --out out
```

- Повторно загружаются только изменённые пакеты. Прошлую версию утилита сама берёт из опубликованного `build/manifest.json` в `main`, и пакеты, у которых не изменилось содержимое, новый манифест берёт из старых релизов. В конце утилита печатает, что и почему пойдёт в загрузку (`new` / `changed`).
- `--previous <файл>` берёт прошлый манифест из файла, `--fresh` упаковывает и загружает всё заново. Если опубликованный манифест не удалось скачать, утилита останавливается, а не перезаливает всё молча.
- Каждый файл читается не больше одного раза за запуск: хэш считается в том же проходе, что и упаковка. Хэши запоминаются в `<инстанс>\.lyno\pack-cache.json`, поэтому неизменённые файлы (тот же размер и время изменения) при следующих запусках не читаются вовсе. `--no-cache` заставляет перечитать всё.
- Если упаковку прервать (Ctrl+C, сбой), запустите ту же команду снова: готовые пакеты из `--out` подхватятся, упаковка продолжится с недоделанного мода.
- После упаковки в `--out` остаются только пакеты этой версии, чтобы в загрузку не попало лишнее. Повторно выпустить уже опубликованную версию утилита не даст.
- Узкое место — диск. Держите `--out` на другом физическом диске, лучше SSD, и добавьте папку инстанса и `--out` в исключения антивируса: Защитник Windows проверяет каждый прочитанный и записанный файл.
- Единица загрузки — мод целиком. Если в моде на 5 ГБ изменился один файл, загрузится весь мод. Поэтому держите настройки в отдельном маленьком моде (см. «Настройки модов»).
- Авторы модов подтягиваются с Nexus, если задан `NEXUS_API_KEY` (ключ берётся на nexusmods.com → Site preferences → API Keys). Название мода на Nexus и его id берутся из `meta.ini`, который MO2 заполняет при установке с Nexus.
- id мода берётся из имени папки. Чтобы переименование папки не перекачивало мод, задайте постоянный id в `meta.ini`: секция `[LYNO]`, ключ `id=`.
- Перед сборкой закройте игру и MO2 и разберите `overwrite/` (см. «Настройки модов»). Предупреждения `lyno-pack` читайте все.
- Профильные настройки игры и локальные сохранения в профиле сборки лучше выключить: эти файлы всё равно не попадут в сборку.

Затем опубликуйте сборку из клона репозитория, в актуальной ветке `main`:

```sh
target/release/lyno-pack publish --out out
```

`publish` создаёт релиз `build-<версия>`, загружает в него новые пакеты, проверяет по HTTP, что скачивается каждая часть манифеста (включая части из старых релизов), и только после этого коммитит и пушит `build/manifest.json` в `main`. Лаунчеры видят новую версию, как только манифест появится в `main`; raw.githubusercontent.com кэширует файл на несколько минут. Если загрузка оборвалась, запустите `publish` ещё раз: уже загруженные файлы он пропустит.

Старые релизы не удаляйте. Неизменённые моды новый манифест берёт из релиза, где они были загружены впервые.

Если в новой версии базового пакета каких-то файлов больше нет (например, вы удалили плагин MO2), лаунчер удалит их у игроков. Сохранения и `UserSettings.json` профиля он не трогает.

## Структура

| Путь | Что это |
|---|---|
| `crates/core` | `lyno-core`: манифест, пакеты, загрузка, установка, план обновления, MO2, поиск игры |
| `crates/pack` | `lyno-pack`: упаковка инстанса в релиз |
| `apps/launcher` | Лаунчер: Tauri 2 + React + TypeScript + Tailwind |
| `docs/` | [Выпуск сборки и лаунчера](docs/release-process.md), справка для разработки: [Cyberpunk под MO2](docs/cyberpunk-mo2.md), [формат инстанса MO2](docs/mo2-instance.md) |

## Разработка

```sh
cargo test -p lyno-core -p lyno-pack     # ядро, включая сквозной тест сборка → установка → обновление
cd apps/launcher && pnpm install
pnpm dev                                 # UI в браузере на мок-данных
pnpm tauri dev                           # приложение целиком (Windows)
```

Подписанный установщик для игроков собирает `launcher-release.yml` (см. [выпуск лаунчера](docs/release-process.md#лаунчер)). Тестовый неподписанный установщик собирается вручную: Actions → CI → Run workflow, артефакт `lyno-hardwired-setup`.
